# Safety warnings for unverified allergen and ingredient info

## Description

Serves S2-4 by making clear that the allergen and diet data behind the Menu tab is not verified. S2-4.2 filters the menu using the dining hall's icon list (the `allergens` column). Those icons can be missing, wrong, or spelled in ways the app doesn't recognize, and the kosher rule is only a guess. Students with allergies or strict diets need to see this on every item, not just on the Settings screen.

Out of scope:

- Checking allergens against a list the student saves (for example "no peanuts"). S2-4.1 does not collect allergens.
- Changing which items the dietary filter keeps or hides. The S2-4.2 rules stay as they are.
- Getting better data from the scraper or adding a verified data source.

## Specs

- Add a pure module at `apps/mobile/src/lib/food/safety-info.ts` with no React or React Native imports. It builds on `getFoodTags` and `normalizeFoodTag` from `dietary-filter.ts`.
- Group the canonical tags:
  - **Allergen tags**: `milk`, `egg`, `fish`, `shellfish`, `soy`, `wheat`, `sesame`, `peanut`, `tree-nut`.
  - **Ingredient tags**: `pork`, `beef`, `alcohol`.
  - **Diet tags**: `vegan`, `vegetarian`, `halal`, `gluten-friendly`.
- `getFoodSafetyInfo(item, activeRestrictions)` returns:
  - `allergens`: display labels for the item's allergen tags, in the order above (for example `["Milk", "Tree nut"]`).
  - `ingredients`: display labels for the ingredient tags.
  - `diets`: display labels for the diet tags.
  - `unrecognized`: raw icon values that `normalizeFoodTag` can't map, trimmed, empty values dropped, duplicates removed, in their original order.
  - `noLabels`: `true` when the item has no icons at all (after dropping empty values).
  - `restrictionNotes`: one note per active restriction that the item passes without proof:
    - **kosher**: always "Not confirmed kosher. The dining halls don't label kosher food."
    - **halal**: when the item has no `halal` icon and passes only because it is vegetarian, "Halal not labeled. Shown because it's marked vegetarian."
    - **pescatarian**, **vegan**, **vegetarian**: none, because those rules need a matching icon.
- `ALLERGEN_DISCLAIMER`: one shared sentence, "Allergen and ingredient info comes from dining hall labels and isn't verified. If you have a food allergy, check with dining hall staff."
- Food card (`components/food/food-card.tsx`):
  - Accept an optional `restrictions` prop (defaults to none).
  - Show allergens as warning-colored chips under a "Contains" label, separate from diet and ingredient chips. Unrecognized icons are still shown as plain chips so no label from the dining hall is dropped.
  - Show an "Unverified" indicator next to the label chips, so every card with labels says the labels are not checked.
  - When `noLabels` is true, show "⚠︎ No allergen info listed. Ask dining hall staff." in the warning style.
  - Show each restriction note in the warning style.
  - Add the allergens, the unverified status, the missing labels message, and the restriction notes to the card's accessibility label.
- Menu screen (`app/(tabs)/menu.tsx`):
  - Show `ALLERGEN_DISCLAIMER` at the top of the list while items are listed.
  - Pass the active restrictions to each card only while dietary filters are applied. When "Show all" is on, no restriction notes appear.
- Food Preferences screen: add to the existing notice that kosher filtering is a best guess, because the dining halls don't label kosher food.

## Requirements

- No new runtime dependencies, and no changes to the API, database, scraper, or stored preference format.
- The S2-4.2 filter rules and results stay the same.
- Unknown icons are never treated as an error and never dropped from the card.
- Existing tests keep passing.
- `npm test`, `npm run lint`, and `npx tsc --noEmit` pass in `apps/mobile`.

## Acceptance criteria

1. Every food card with labels shows them as unverified.
2. Allergen icons appear as warning chips under "Contains" and are separate from diet icons such as Vegan or Halal.
3. A food with no icons shows "No allergen info listed. Ask dining hall staff."
4. With Kosher saved and filters applied, every listed item says it is not confirmed kosher.
5. With Halal saved, a vegetarian item without a Halal icon says halal is not labeled. An item with a Halal icon has no note.
6. With "Show all" on, no restriction notes appear.
7. The Menu list shows the allergen disclaimer.
8. Icons the app doesn't recognize still appear on the card.
9. Screen readers read the allergens, the unverified status, and any warnings.

## Tests

- Jest unit tests in `apps/mobile/src/lib/food/__tests__/safety-info.test.ts`:
  - Grouping into allergens, ingredients, and diets, with real scraper spellings (`Tree Nut`, `Gluten Friendly`) and mock spellings (`eggs`).
  - `unrecognized` keeps unknown values, drops empty ones, and removes duplicates.
  - `noLabels` for an empty list and for a list of only blank values.
  - Restriction notes: kosher always, halal only when inferred from vegetarian, none for vegan, vegetarian, or pescatarian, and none with no restrictions.
  - Mock data check: every mock item that passes the kosher filter gets the kosher note.
