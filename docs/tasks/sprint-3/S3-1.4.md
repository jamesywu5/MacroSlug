# Confirm when a food is added and test the add-to-log flow

## Description

Serves S3-1 by telling the student their food was logged, and by testing the flow from adding a food through reading it back and totaling it.

## Specs

- After a successful save the sheet closes and a confirmation reads, for example, "Added 2 servings of Cheese Pizza to today's log". It shows for 3 seconds and is announced to screen readers.
- If saving fails, the sheet stays open with an error and nothing is saved.
- Entries are saved on the device (`apps/mobile/src/features/daily-log/storage-core.ts`, key `macroslug.daily-log.v1`) because the app has no sign-in yet, so it can't call `POST /api/log-entries` from S3-1.2. Entries use the same field names as that API (`food_name`, `serving_quantity`, `consumption_date`, `calories`, `protein`, `carbohydrate`, `fat`) and snapshot the per-serving values, so they plug into `calculateDailyTotals` (S3-2.1) and can move to the API later.
- `consumption_date` is the device's local day, so late-evening meals count for the right day.
- Saves run one at a time, so quick repeated taps can't overwrite each other.
- Tests (`entries.test.ts`, `storage.test.ts`) cover the full flow, quantity limits and steps, null versus zero nutrition, local dates, separate days, duplicate foods, overlapping saves, failed saves, and damaged saved data.
