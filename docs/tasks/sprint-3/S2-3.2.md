# Validate nutrition goal inputs

## Description

Serves S2-3 by validating the Nutrition goals form built in S2-3.1 so that only blank or non-negative numeric targets can be saved. Saving goals to local storage or Supabase (S2-3.3) and writing unit tests for validation and persistence (S2-3.4) are out of scope.

## Specs

- Add a pure validation module at `apps/mobile/src/features/nutrition-goals/validation.ts` with no React or React Native imports, so persistence code and tests can use it directly.
- Add a parsed goals type to `types.ts`:
  - `NutritionGoals` is `{ calories, protein, carbs, fat }`, where each value is a `number` or `null`.
  - `null` means the goal is not set.
- `validateNutritionGoal(field, raw)` checks one field and returns `{ value: number | null, error: string | null }`.
- `validateNutritionGoals(input)` checks all four fields and returns either:
  - `{ ok: true, goals: NutritionGoals }`, or
  - `{ ok: false, errors }`, where `errors` maps each invalid field to its message.
- Validation rules for each raw string:
  - Leading and trailing whitespace is ignored.
  - An empty or whitespace-only value is valid and becomes `null`, meaning no goal is set for that nutrient.
  - Calories must be a whole number made of digits only, such as `2000`.
  - Protein, carbohydrates, and fat must be digits with at most one decimal point and at least one digit, such as `85`, `85.5`, or `.5`.
  - `0` is valid.
  - Negative values, letters, symbols, commas, exponents such as `1e3`, more than one decimal point, a lone `.`, `NaN`, and `Infinity` are invalid.
  - An invalid value returns `value: null` with an error. It is never partly parsed. For example, `.` does not become `0` and `12g` does not become `12`.
- Error messages are short and say what to fix, for example "Enter a positive number" or "Calories must be a whole number."
- Placeholders in `NUTRITION_GOAL_FIELDS`:
  - Each field has an example placeholder: `2000` for calories, and `0.0` for protein, carbohydrates, and fat. These replace the current "Not set" placeholder.
  - Placeholders show only while a field is empty. They use a muted placeholder color that is clearly dimmer than entered values, so a student can tell an example from a real value.
  - Placeholders are display hints only. An empty field still saves as `null`, not as the placeholder value.
- Screen behavior in `nutrition-goals-screen.tsx`:
  - Pressing Save goals validates all fields.
  - If any field is invalid, `onSave` is not called, nothing is saved, and every invalid field is highlighted in red with its error shown below the input.
  - If all fields are valid or blank, `onSave` is called. Blank fields are passed as `null`, so no goal is set for those nutrients.
  - Editing a field clears that field's red highlight and error.
  - Error text is exposed to screen readers.
- `onSave` now receives parsed `NutritionGoals` instead of raw strings. The route keeps logging the payload until S2-3.3 replaces it with persistence.

## Requirements

- No new runtime dependencies, and no changes to the API, database, or scraper.
- Do not add storage or Supabase code in this task.
- Validation functions must not change their input.
- Keep the field definitions in `NUTRITION_GOAL_FIELDS` as the single source of field keys and labels.
- Existing tests must keep passing. Update the S2-3.1 Save payload test only if the changed `onSave` contract requires it.
- `npm test`, `npm run lint`, and `npx tsc --noEmit` pass in `apps/mobile`.

## Acceptance criteria

1. Saving with every field blank or whitespace-only calls `onSave` with every goal set to `null`.
2. Saving with some fields filled and others blank calls `onSave` with numbers for the filled fields and `null` for the blank ones.
3. Saving valid values such as `2000`, `120`, `210.5`, and `.5` calls `onSave` with the matching numbers.
4. Whitespace around a valid value is ignored.
5. A negative value in any field blocks Save, highlights that field in red, and shows an error under it.
6. Non-numeric input, such as `.`, `abc`, `12g`, `1,000`, `1e3`, or `1.2.3`, blocks Save, highlights that field in red, and shows an error under it. The validator returns `value: null` for that field.
7. A decimal calories value, such as `2000.5`, blocks Save and highlights Calories in red with an error.
8. Only invalid fields are highlighted, and editing a field clears its highlight and error.
9. Empty fields show the placeholders `2000`, `0.0`, `0.0`, and `0.0` in a muted color that is dimmer than entered values, and the placeholders are never saved as values.
10. `validateNutritionGoal` and `validateNutritionGoals` can be imported and run without React Native.
