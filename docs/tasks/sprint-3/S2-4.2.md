# Filter menu items by dietary restrictions

## Description

Serves S2-4 by using the dietary restrictions saved in S2-4.1 to hide menu items that don't fit them. Filtering runs on the device, the same way `filterFoods` already handles dining hall and meal. The only data each food has is the dining hall's icon list (the `allergens` column, for example `["Vegan", "Soy", "Gluten Friendly"]`), so every rule below works from those icons.

Out of scope:

- Safety warnings and "unverified" indicators on food cards. Those come in S2-4.3.
- Ranking or filtering by the food preferences (`high-protein`, `lower-carb`). Those are preferences, not restrictions. Hiding food based on macro thresholds would also hide items whose macros are missing, so they are left for recommendation work.
- Allergen restrictions such as "no peanuts". S2-4.1 does not collect them.

## Specs

- Add a pure module at `apps/mobile/src/lib/food/dietary-filter.ts` with no React or React Native imports.
- Icon normalization:
  - `normalizeFoodTag(raw)` lowercases the value, trims it, and collapses inner whitespace. It then maps known spellings to one canonical tag. It returns `null` for empty values and for values it doesn't recognize.
  - Canonical tags: `vegan`, `vegetarian`, `halal`, `gluten-friendly`, `pork`, `beef`, `fish`, `shellfish`, `alcohol`, `milk`, `egg`, `soy`, `wheat`, `sesame`, `peanut`, `tree-nut`.
  - Known spellings include both the real scraper values (`Vegan`, `Gluten Friendly`, `Egg`, `Tree Nut`) and the mock data values (`eggs`, `tree nuts`). Singular and plural forms map to the same tag.
  - `getFoodTags(item)` returns the set of canonical tags for a `FoodItem`.
- Compatibility rules for `isCompatibleWithRestriction(tags, restriction)`. An item passes only if its icons show that it fits. A missing icon never counts as proof that an item fits.
  - **vegan**: has `vegan`.
  - **vegetarian**: has `vegan` or `vegetarian`.
  - **pescatarian**: fits vegetarian, or has `fish` or `shellfish` and has neither `pork` nor `beef`.
  - **halal**: has no `pork` and no `alcohol`, and either has `halal` or fits vegetarian.
  - **kosher**: the dining halls have no kosher icon, so this is a best-effort exclusion. An item fails if it has `pork` or `shellfish`, or if it has both `beef` and `milk`. Anything else passes. Code comments must say this rule is unverified so S2-4.3 can flag it.
- `filterByDietaryRestrictions(items, restrictions)` returns `{ items, hiddenCount }`.
  - An item is kept only if it passes every selected restriction.
  - An empty restriction list returns all items with `hiddenCount: 0`.
  - Item order is preserved and the input array is not changed.
- Menu screen (`apps/mobile/src/app/(tabs)/menu.tsx`):
  - Load saved preferences with `loadFoodPreferences`. Reload them each time the tab gains focus (`useFocusEffect`), so changes made in Settings apply when the student comes back.
  - Apply `filterByDietaryRestrictions` before the hall and meal filters. Meal counts should then reflect only the items the student can eat.
  - When any restriction is active, show a small banner under the filters. It reads "Filtered for: Vegan, Halal · N hidden" and has a "Show all" toggle. Turning the toggle on shows unfiltered results for the current visit only and does not change saved preferences.
  - If loading preferences fails, show the unfiltered menu with no banner. A preference error must never block the menu.
  - When filters leave a meal empty, say so in the empty state, for example "Nothing matches your dietary filters for this meal."
- Mock data (`mock-foods.ts`): add diet icons (`vegan`, `vegetarian`, `halal`, `pork`, `beef`) to the existing rows so every restriction has visible effects with the mock source. Do not change names, macros, or row count.
- Food Preferences screen: change the notice to say dietary restrictions now filter the Menu tab, and that allergen information comes from dining hall labels and is not verified.

## Requirements

- No new runtime dependencies, and no changes to the API, database, or scraper.
- Use the existing `DietaryRestrictionId` type and storage from `features/preferences` as they are. Do not change the stored format.
- Unknown icons are ignored, never treated as an error.
- Existing tests must keep passing. Update existing `filterFoods` or mock data assertions only where the new diet icons require it.
- `npm test`, `npm run lint`, and `npx tsc --noEmit` pass in `apps/mobile`.

## Acceptance criteria

1. With no restrictions saved, the Menu shows exactly the same items as before this task, with no banner.
2. With Vegan saved, only items with the Vegan icon appear. Items with no icons at all are hidden.
3. With Vegetarian saved, items with the Vegan or Vegetarian icon appear.
4. With Pescatarian saved, vegetarian items and fish or shellfish items without beef or pork appear.
5. With Halal saved, items with the Halal icon appear, and so do vegetarian items without alcohol. Any item with pork or alcohol is hidden.
6. With Kosher saved, items with pork or shellfish, or with both beef and milk, are hidden.
7. With two restrictions saved, only items that pass both appear.
8. The banner names the active restrictions and the hidden count, and "Show all" temporarily shows the full menu.
9. Changing restrictions in Settings and returning to the Menu updates the results without restarting the app.
10. If preferences fail to load, the menu still loads unfiltered.
11. Icon matching ignores case and whitespace, and the real scraper spellings (`Gluten Friendly`, `Egg`) match the same as the mock spellings (`eggs`).

## Tests

- Jest unit tests in `apps/mobile/src/lib/food/__tests__/dietary-filter.test.ts`:
  - `normalizeFoodTag`: case, whitespace, synonyms, plurals, and unknown or empty values.
  - Each restriction rule, including the edge cases: no icons, pescatarian with fish plus pork, halal vegetarian with alcohol, kosher with beef plus milk.
  - `filterByDietaryRestrictions` with no restrictions, combined restrictions, `hiddenCount`, preserved order, and an unchanged input array.
  - Mock data check: every restriction keeps at least one item and hides at least one item.
