# S2-4.1: Dietary restrictions and food preferences UI

## Description

As a student, I want to specify dietary restrictions and food preferences so that unsuitable options can be filtered from my recommendations.

## Specs

- Add a Food Preferences screen reachable from the Home screen's settings button.
- Provide multi-select dietary restriction options for vegetarian, vegan, pescatarian, halal, and kosher.
- Provide multi-select food preference options for high protein and lower carb.
- Show selected and unselected states for each option, with actions to clear all selections and save preferences.
- Store selections on the device and show loading, save confirmation, and error states.
- Explain that recommendation filtering and allergen verification are not implemented by this task.

## Requirements

- Represent selections using stable option IDs rather than display labels.
- Load saved selections when the screen opens and sanitize stored data by removing invalid or duplicate IDs.
- Persist saved selections locally with an update timestamp; surface load and save failures with a retry action where applicable.
- Do not imply that saved preferences currently filter menu recommendations or verify allergens.

## Acceptance criteria

- A student can navigate from Home to Food Preferences.
- The screen displays all supported dietary restriction and food preference options with clear multi-select states.
- Selecting an option adds its stable ID; selecting it again removes that ID.
- Clear all empties both selections, and Save persists the current selections on the device.
- Previously saved selections are restored when the screen is reopened.
- Loading and persistence failures are communicated to the student, and the screen clearly states that filtering and allergen verification are not yet available.

## Tests

- Unit tests cover the option catalogs, selection toggling, stored-data sanitization, and local persistence behavior.
