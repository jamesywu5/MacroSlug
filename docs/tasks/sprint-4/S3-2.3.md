# Show daily totals next to nutrition goals

## Description

Serves S3-2 (plan Tasks 3 and 4) by adding a Daily Intake screen that shows the calories, protein, carbs, and fat consumed today next to the user's daily goals, using `calculateDailyTotals` (S3-2.1) and `flagMissingValues` / `formatTotal` (S3-2.2). It also adds the story's tests confirming totals update when entries are added, edited, or removed. Sign-in, fetching entries from `GET /api/log-entries`, saving goals, and the screens for adding, editing, or removing entries (S3-4) are out of scope.

## Specs

- `buildDailyTotalsView(entries, goals)` in `apps/mobile/src/features/daily-log/totals-view.ts` takes an array of `LogEntry` and a `NutritionGoals` and returns `{ entryCount, rows, flags }`.
- `rows` has one row per nutrient, in the order calories, protein, carbohydrate, fat. Each row is `{ nutrient, label, unit, consumedText, goal, goalText, remainingText, progress, status }`:
  - `label` and `unit` are Calories / kcal, Protein / g, Carbs / g, Fat / g.
  - `consumedText` is `formatTotal(totals, nutrient)`.
  - `goal` is the matching goal (`carbs` maps to `carbohydrate`), or `null` when no goal is set. `goalText` is the goal as text, or `"No goal set"`.
  - `remainingText` is `"<n> left"` or `"<n> over"` (rounded to 1 decimal place) when a goal is set and the total is known. When some foods are missing data it is `"At most <n> left"` or `"<n>+ over"`. It is `null` when no goal is set or every logged food is missing data.
  - `progress` is consumed ÷ goal, clamped to 0–1, for a progress bar. It is `null` when no goal is set, the goal is 0, or every logged food is missing data.
  - `status` is `"no-goal"`, `"unknown"` (every food missing data), `"under"`, `"met"` (consumed equals goal), or `"over"`.
- `flags` is `flagMissingValues(totals).flags`.
- `DailyTotalsScreen` in `apps/mobile/src/features/daily-log/daily-totals-screen.tsx` takes `entries` and `goals` as props and renders one card per row with consumed, goal, remaining text, and a progress bar. Missing-data flags appear below the cards. With no entries it shows an empty state ("No foods logged today") and still shows the goals.
- A new route `/daily-intake` (`apps/mobile/src/app/daily-intake.tsx`) renders `DailyTotalsScreen` with empty entries and no goals until sign-in and goal saving exist. Tapping the Home "Daily Intake" card opens it.

## Requirements

- No new runtime dependencies, and no changes to the API, database, scraper, `totals.ts`, or `missing-flags.ts`.
- The screen follows the existing theme (`ThemedText`, `ThemedView`, `Spacing`, `useTheme`) and works on iOS, Android, and web.
- Tests use `node:test` and are added to the `test:daily-log` script. `npm test`, lint, and `npx tsc --noEmit` must pass.

## Acceptance criteria

1. `buildDailyTotalsView` returns four rows in the order calories, protein, carbohydrate, fat, with the right labels and units.
2. Each row shows consumed amounts from `formatTotal`, so unknown values are shown as `+` or `"—"` and never as `0`.
3. A goal of `null` gives `goalText: "No goal set"`, `remainingText: null`, `progress: null`, and `status: "no-goal"`.
4. Remaining text, progress, and status are correct for under, met, and over goal, and `progress` is clamped to 1 when over.
5. When some foods are missing data, remaining text is worded as a bound ("At most <n> left" or "<n>+ over"). When every food is missing data, `status` is `"unknown"` and `progress` and `remainingText` are `null`.
6. Totals and rows update when an entry is added, when an entry's serving quantity or nutrition values are edited, and when an entry is removed, including removing the last entry.
7. The input entries and goals are not changed.
8. Tapping the Home "Daily Intake" card opens the Daily Intake screen, which shows the empty state and four goal cards.
